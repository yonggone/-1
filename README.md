모바일에서는 컴퓨터와 같은 네트워크에 연결한 뒤 `http://컴퓨터의IP주소:8080`에 접속하세요. 같은 서버에 접속한 기기들은 계정과 프로필을 공유합니다. 현재 서버는 로컬 네트워크용이며 인터넷 공개 시 HTTPS와 운영 서버 설정이 필요합니다.

- 화살표: 이전/다음 달 이동 (연도 자동 전환)

## GitHub 및 Render 적용 방법

1. 바탕화면 `로그인유지_업로드파일` 폴더를 엽니다.
2. 폴더 안의 파일들을 GitHub 저장소 첫 화면에 업로드하고 기존 파일을 교체한 뒤 커밋합니다. 이번에는 화면 기능도 추가되어 server.py/database.py 두 개만 교체하면 안 됩니다.
3. Render Root Directory: 비움 (저장소 첫 화면에 server.py가 보일 때).
4. Build Command: `pip install -r requirements.txt`
5. Start Command: `python server.py`
6. Environment: 기존 `DATABASE_URL`과 Neon의 기존 프로젝트/브랜치/DB를 그대로 사용합니다. 다른 빈 DB 주소로 바꾸지 마세요. `/healthz`를 상태 확인 경로로 쓸 수 있습니다.
7. 재배포합니다. 이전 로그인 유지 버전의 유효한 세션은 그대로 사용할 수 있습니다. 메모리 세션을 쓰던 옛 버전에서 넘어왔다면 한 번 다시 로그인해야 합니다.

계정·게시물·DB를 삭제할 필요가 없습니다. 시작 시 `CREATE TABLE IF NOT EXISTS`와 누락 칼럼 추가만 수행합니다. 기존 비밀번호를 초기 비밀번호로 덮어쓰지 않습니다. Neon 연결 실패 시 임시 SQLite로 우회하지 않으며 Render에서 DATABASE_URL이 비어 있으면 실행을 중단합니다.

로그인은 로그인 시점부터 30일 유지됩니다. 로그아웃하면 해당 세션을 삭제하고, 비밀번호 변경 시 해당 계정의 이전 세션을 모두 폐기합니다. 쿠키 삭제·시크릿 모드 종료·다른 브라우저에서는 다시 로그인해야 합니다. DB에는 쿠키 원문 대신 SHA-256 해시를 저장합니다.

최종본 원본 ZIP의 `.data/board.sqlite3`에는 기존 계정 35개와 자리배치 34개가 있으며 수행평가·공지·앨범 게시물은 0개였습니다. 이 파일은 원본 ZIP에 그대로 보관되어 있습니다. 업로드 폴더/배포 ZIP에는 개인정보가 들어 있는 로컬 DB, 로그, 캐시를 넣지 않았습니다. 원본 ZIP은 GitHub에 올리지 말고 보관하세요. 로컬 SQLite 자료를 기존 Neon 데이터와 합치는 작업은 자동으로 수행하지 않습니다.

## 검증

`python -m unittest -v test_server.py`는 임시 SQLite에서 가상 하루 경과 및 서버 재시작 후 로그인·게시물·사진·프로필·자리배치 보존과 수정/삭제, 권한, 세션 폐기/만료를 검증합니다. 같은 테스트를 임시 PostgreSQL에서도 통과했고 기존 스키마 업그레이드 시 계정·비밀번호·유효 세션 보존을 확인했습니다. 실제 운영 Neon/Render에는 접근하지 않았습니다.
